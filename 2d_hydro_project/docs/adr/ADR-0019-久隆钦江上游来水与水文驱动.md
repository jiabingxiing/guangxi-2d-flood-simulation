# ADR-0019：久隆钦江上游来水与水文驱动（小时级 Q(t) 与防重复计量）

- **状态**：已接受（Accepted）。授权来源：`plans/code_artifact.md` 执行批准（2026-11-22，用户批准任务 4/5 lisflood.exe 运行）。
- **日期**：2026-11-22
- **触发**：久隆基线为纯雨驱动、`Qin ≡ 0`，钦江干流来水完全缺失（计划 §2.1）；久隆被排除在 ADR-0016 入流构建之外，且日尺度 GR4J 均分 24 h 会抹平台风洪峰（计划 §2.4）。
- **关联**：ADR-0016（贵港/宁明入流与 GR4J）、ADR-0020（河道表达）、`configs/cases/jiulong_hydro.yaml`。

## 背景

1. 陆屋水文站（108°57′E, 22°17′N）控制 ~1,400 km²，位于模型入域断面上游；A1（模型外上游集水区）实测 1,775 km²（GLO-30 派生，自洽区间 [1000, 2600]）。
2. 凭证类数据本机不可得（2026-11-22 实测）：IMERG V07 粒度文件需 Earthdata 认证（401）、CDS 无 key → 降雨降级 Open-Meteo ERA5 逐时（UTC+8 本地时，缓存 `data/interim/inflow/`）。
3. 8 月面雨量 313 mm（锚点实测）→ 35 d 暖启动后土壤蓄满（F_max=120 mm），台风期前期含水率饱和是事实约束。

## 决策

1. **A1/A2 分账（防重复计量红线 2）**：A1=1,775 km² 产流只进 N 缘 QVAR（`qinjiang_event_5d.bdy`，文件值=Q/200）；A2=200 m 域内净雨只进 `.rain`（`rain_net_ga_5d.rain`）。`run_jiulong_dual_forcing.py` 组装时断言 par 无 `infiltration/fc` 键（红线 1 硬锁）。
2. **事件模型（方案 B 降级实现）**：`scripts/common/event_hydro.py` = Green-Ampt 产流 + SCS 无因次 UH 汇流（1 h 步长）。UH 幅值按**体积守恒标定**（每 10 mm·km² = 1e4 m³；folklore 2.08 系数在 Δt=1 h 下有 ~29% 截断损失，弃用）。
3. **体积先验（方案 B/C 合成口径）**：洪峰形态取 GA+SCS-UH，事件体积缩放到日尺度 GR4J 先验（复用 `build_inflow_hydrology.run_gr4j`，X1=350/X2=0/X3=90/X4=1.7，文献中值未率定）；缩放系数限幅 [0.4, 2.5]，越界告警保持原值。**禁止日均分 24 h 作为驱动**（形态不经过 GR4J）。
4. **定版参数（2026-11-22 冻结）**：GA = Ks 3.5 mm/h、ψ 300 mm、θs 0.45、θi 0.32、F_max 120 mm、暖启动 35 d（2024-08-01 起）；Tp=5 h；A2 净雨口径 = 暖启动 + 饱和后入渗容量回落 drainage=Ks（preprocessor docstring 语义，系数 ~0.32）；A1 体积系数 = GR4J 先验 0.44。
5. **定版 Q(t)**：事件窗峰值 **1,398 m³/s @ t0+69 h**（2024-09-07 夜，对应 ERA5 面雨峰 74.9 mm/24h），事件体积 97 Mm³；`validate_jiulong_hydrograph.py` 校验 PASS（时间轴 3600 s 递增、QVAR 量化对齐、体积守恒偏差 <1%）。敏感性 0.7/1.0/1.4 档入审计（audit-only，不写 bdy）。
6. **对照与审计**：GR4J 对照入 `data/catalog/jiulong_inflow_audit.json`（evidence_level E3）；陆屋站实测逐时资料获取后按方案 A 重生成并换 run tag 重跑，本版不作率定。

## 验收方法

- `validate_jiulong_hydrograph.py` 全项 PASS；`res.mass` ∫Qin 与 bdy ∫Q 相对偏差 ≤1%（`audit_jiulong_coupling.py`）；质量门 `E_mass ≤ 1e-3`。

## 不适用条件与回滚

- 取得陆屋/久隆站 2024-09 逐时实测 → 本 ADR 的模型估算降级为对照，方案 A 实测驱动接管。
- GR4J 缩放系数越界或 A1 面积复核（priors `pending_user_review`）变化 >10% → 重新生成 bdy 并以新 run tag 重跑，不覆盖旧 run（`guard_no_overwrite`）。
