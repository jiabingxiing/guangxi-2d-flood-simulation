# ADR-0010：久隆直接降雨模型治理规范

- **状态**：已接受（Accepted；本 ADR 由 `plans/久隆水动力推演效果改进实施计划_从伪影诊断到全链条治理.md` v3.0 定版，分辨率默认口径为方案 A）。**方案 A 是本 ADR 的默认工作口径，不是用户已确认的最终选择**：Phase 0 产出 `diagnostics/jiulong/phase0-v1/resolution_comparison.json` 的 `decision_input.status` 仍记「未冻结：方案 A/B 需用户确认后才能冻结展示阈值」。用户确认前，本 ADR 允许按 200 m 编制展示治理，但**不得冻结具体 A/B/C 阈值数值**。
- **日期**：2026-10-31
- **触发**：久隆 2024-09 摩羯情景的推演效果出现孤立点状斑块、规则几何色块与退水不合理三类问题；排查确认成因分布在数据、网格、地形预处理、产流假设、排水边界和展示口径六处，需要单一 ADR 锁定口径，防止后续把展示滤波当物理修复、把 100 m 规则套到 200 m 生产结果、把 `FAIL-EXPLAINED` 计为通过。

## 背景

1. **生产网格是 200 m，不是 100 m。** 200 m 生产基线 `scen_free_200m_sv6h`（21 帧，`saveint=21600`，`sim_time=432000`，`fpfric=0.035`，`acceleration` 求解器）湿面积 **263.24 km²**（`res.max` 口径，水深 > 0.05 m，剔除 27 个海域像元），`E_mass = 4.893e-4` PASS。100 m 敏感性 run `scen_free_100m_dt2p5_sv6h_realdem`（21 帧，`initial_tstep=2.5`）湿面积 **271.07 km²**（剔除 97 个海域像元），`E_mass = 3.089e-4` PASS。同一情景两者差 **+7.83 km²（+2.97%）**，但最大水深与站址邻域水深差异明显。
2. **"4/9 像元"不是跨分辨率稳定的物理阈值。** 实测栅格头：200 m 单元面积 40,000 m²（0.04 km²），100 m 单元面积 10,000 m²（0.01 km²），相差 4 倍。因此 4 格在 100 m 是 0.04 km²、在 200 m 是 0.16 km²；9 格在 100 m 是 0.09 km²、在 200 m 是 0.36 km²。把 100 m 规则直接套到 200 m，会把四倍物理面积的斑块误判为同一类对象。Phase 0 实测（`diagnostics/jiulong/phase0-v1/resolution_comparison.json`，E1）：同一 0.04 km² 物理阈值下，200 m 需 1 格、100 m 需 4 格；斑块数 1107 vs 1037，保留面积 263.24 vs 223.91 km²（比值 0.851）——同一物理阈值在两种网格上保留的面积差 15%，说明**阈值必须按物理面积定义，像元数只能是换算结果**。
3. **既有展示层不合规且改动量极大。** `outputs/jiulong/2024-09-yagi/scen_free_100m_dt2p5_sv6h_realdem_cleaned` 的 `clean_audit.json` 写死 `Connected components <= 4 cells (<=0.04 km2)` 与 `<= 9 cells with max_depth < 0.15m`，并把 `<=0.04 km2` 当作跨网格常量（该值只在 100 m 成立）；`filter_standard` 写 `ARR 2019 Book 9 & UK EA Multi-Criteria Rain-on-Grid Filter`。实测该层在 `res.max` 上把湿面积从 271.07 km² 压到 171.97 km²（**−99.10 km²，−36.56%**），水量从 168.43 Mm³ 压到 78.90 Mm³（**−89.53 Mm³，−53.16%**），且未在产物中登记体积变化率。
4. **该目录曾破坏质量门扫描契约，已按本 ADR 修复。** 它含 `results/res.mass`（SHA-256 前 16 位 `6fc7b11c61aa6acc`，与源 run 逐位相同）且含 `run.log`；`scripts/stage3/g15_mass_recheck.py` 原扫描条件（`rglob("results/res.mass")` + `run.log` 存在 + 非 `_v1invalid`/`_v1_polyfitbed`）会把它计为独立 run，污染 PASS 计数。现已加入派生层判定（`meta.json` 的 `not_physical_recalculation`/`derived_from`，或存在 `clean_audit.json`/`display_qc_audit.json`），并登记到 `mass_recheck_g15.json` 的 `excluded_variants`。
5. **质量门现状存在明示不合格项。** `data/catalog/mass_recheck_g15.json`（2026-10-31 21:15 重算，含派生层排除）全表 **39 PASS / 3 FAIL-EXPLAINED / 0 FAIL**（共 42 run）。久隆 10 个有效 run 为 **7 PASS / 3 FAIL-EXPLAINED**：`scen_z05_200m`（HFIX，1.223e-2）、`scen_z10_200m`（HFIX，3.705e-2）、`scen_ztide_200m`（HVAR，4.06e-2）为 FAIL-EXPLAINED，**不计通过**。
6. **退水异常已定量证实，且不能用滤波掩盖。** 延长退水 run `scen_free_200m_sv6h_recession`（53 帧，`sim_time=1123200`）`E_mass = 5.3e-4` PASS；模型 09-10→09-17 湿面积 **+27.68 km² 不降反增**，而 S1 09-17 水体约 12.2 km²，方向相反（`data/catalog/jiulong_recession_s1.json`，判 `WEAK`）。
7. **久隆没有独立验证硬门。** 无近洪峰观测、无连续水位/流量过程；仅有灾前/退水后 S1 弱证据。CSI、POD、FAR、NSE、R²、水深误差当前**未测**，不得写成硬门指标。

## 决策

### 1. 四层 DEM 契约

地形按四个职责层管理，层间不得静默互相替代。

| 层 | 用途 | 允许操作 | 必须记录 |
|---|---|---|---|
| `DEM_RAW` | 原始归档 | **不修改**，只登记 | 来源、SHA-256、NoData、垂直基准状态 |
| `DEM_REPAIRED` | 修复已确认的无效值 | 仅局部、必须有来源依据 | 像元差异数、修复原因、不确定度 |
| `DEM_HYDRO` | D8、汇流、连通性分析 | 选择性填洼（Priority-Flood） | 填洼区域、填洼体积、流向变化 |
| `DEM_HYDRAULIC` | 水动力求解输入 | 保留真实洼地；按有来源资料修结构 | 修改清单、版本、回滚路径 |

- **`DEM_HYDRO` 不得直接替代 `DEM_HYDRAULIC`。** 任何替代必须经过独立试验、质量门和新 run tag，并有用户批准记录；未批准的替代只能作为候选输入登记。
- 禁止全域统一钳位负值 DEM。负值必须先分类为「无效值 / 真实水体 / 基准或产品异常」三类，再按类处理。久隆负值约 319.5 km² 而 S1 常水约 11 km²，约 96% 负值不能直接视为海面。
- 禁止全域固定刻蚀 0.5–1.5 m；禁止默认施加全域最小坡度 0.0005。
- 填洼后仍须检查平坦面与水力连通性；**不得表述为「Priority-Flood 不会制造平坦面」**。
- 每一层写出 GeoTIFF 时必须带 CRS、分辨率、nodata 和 SHA-256；层契约清单落 `data/catalog/jiulong_dem_layers.json`。

### 2. 分辨率口径

- **200 m 为生产治理基线**（方案 A）。所有展示阈值、验收门槛与对外产品按 200 m 口径编制。
- **100 m 仅作敏感性对照。** 100 m 结果不得升级为生产基线，不得作为默认展示层。
- 跨分辨率比较**必须使用同一物理面积阈值（km²）**，并同时报告：物理面积、斑块数量、统一物理半径内的最大/分位水深、总蓄水量、出口量、降雨量、同一事件窗口与同一输出时间、同一河沟/边界参数化方式、输入地形版本与参数哈希。
- **禁止只比像元数、像元百分比或斑块个数。** 斑块个数的差异在 4 倍单元面积下不构成物理结论。
- 方案 B（100 m 或更细分辨率完整物理重跑后治理）需用户单独批准；批准前不冻结 100 m 阈值、不切换默认生产层。

### 3. 阈值预注册

- 展示阈值只用两个口径：**物理面积阈值（km²）** 与 **持续性阈值（连续帧数）**。水深阈值属项目候选参数，**不自动归因于国际规范**。
- 像元数一律由栅格头换算，公式固定为：

  ```text
  n_cells = ceil(area_threshold_km2 * 1e6 / cell_area_m2)
  cell_area_m2 = cellsize_m ** 2        # cellsize_m 从栅格头读取
  ```

- **禁止写死 4 像元、9 像元或 100 m 单元面积。** 审计 JSON 必须逐档写入 `cellsize_m`、`cell_area_m2` 与换算后的 `n_cells`。
- A/B/C 三档参数**必须在处理前登记**并计算参数哈希，写入 `data/catalog/jiulong_display_qc_audit.json`；**禁止按结果截图事后挑选参数**。
- 预注册告警：任一档导致湿面积或水量变化超过预注册告警值时，该档只能作为诊断层，标记 `blocked_for_default_publish`，不得默认发布。
- 本 ADR 冻结的是换算公式与登记要求，**不冻结 A/B/C 的具体数值**；具体数值由 Phase 1 在处理前登记，一经登记不得事后放宽。

### 4. 展示层命名与派生标记

- 展示派生层只允许两个名称：`display_qc` 或 `presentation_filtered`。
- **禁止**称展示层为「校准」「真实淹没」「物理修复」，禁止暗示其具有物理意义。
- 每个派生目录的 `meta.json` 必须包含：

  | 字段 | 要求 |
  |---|---|
  | `derived_from` | 源 run 的相对路径 |
  | `not_physical_recalculation` | 必须为 `true` |
  | `param_hash` | 预注册参数集合的哈希 |
  | `source_run_hash` | 源 run 关键产物（`res.max`/`res.mass`）哈希 |
  | `cellsize_m` / `cell_area_m2` | 从栅格头读取，二者满足平方关系 |
  | `param_set_id` | 对应 A/B/C 档编号 |
  | `generated_utc` / `caveats` | 生成时刻与限制说明 |

- 派生层目录**不得含 `res.mass`**；含 `res.mass` 会被 `g15_mass_recheck.py` 计为独立 run，污染质量门计数。`g15_mass_recheck.py` 已按本 ADR 加入派生层判定：`meta.json` 声明 `not_physical_recalculation=true` 或 `derived_from`，或目录存在 `clean_audit.json`/`display_qc_audit.json` 者，不计入质量门；判定用派生标记，不用目录名猜测。
- 派生层必须写逐帧审计：被过滤像元数、面积、水量、斑块数、原因码，以及面积与水量变化率。
- **审计 JSON 的字段层级是契约的一部分**：`data/catalog/jiulong_display_qc_audit.json` 的 `param_sets.<档位>` 必须在档位记录内（顶层，或 `params` 子对象内，两者等价）给出 `cellsize_m`、`cell_area_m2` 与换算后的 `n_cells`，且 `cell_area_m2 == cellsize_m**2`，并声明 `source` 与 `confidence`。这样机器校验能证明「阈值确实是按栅格头换算的」，而不是写死像元数。`tests/test_governance_contract.py::test_display_qc_audit_declares_preregistered_params` 已按此断言。

### 5. 质量门口径

- 质量门三分类，**无第四类，不使用 N/A**：`PASS`（`E_mass ≤ 1e-3`）、`FAIL-EXPLAINED`（HFIX/HVAR 边界超限且有原因）、`FAIL`（其它超限）。
- **`FAIL-EXPLAINED` 不计通过。** 统计通过数时只计 `PASS`。
- **`PASS` ≠ 预测正确。** 质量门只证明水量账目闭合，不证明物理正确、不证明地形可信、不证明边界合理。
- 无记录的项目写 `unrecorded`；未验证的性能指标写「未测」，不得把目标值写成实测值。
- 当前久隆口径：10 个有效 run 中 7 PASS / 3 FAIL-EXPLAINED。**不得表述为「质量门全量通过」。**
- 物理候选 run 必须新 run tag，且写入前检查目标目录：已有 `results/res.mass` 即退出，不覆盖。

### 6. 回滚规则

- **展示层**：切回 raw 即可回滚，**不删除派生产物**。
- **物理候选**：不覆盖旧 run，不自动切换默认 run；默认层切换必须有审批记录。
- **门禁失败**：保留证据，标记 `FAIL` 或 `FAIL-EXPLAINED`；**不得通过删除目录解决**。
- **发布包**：保留最近两个 `bundle_id`，回滚只改启动目标，不删除旧包。

### 7. 禁止表述清单（计划 §2.3 原文）

- 不写「ARR 2019 强制规定 0.1 m、0.3 m、500–2000 m² 或 0.02 m²/s 通用滤波阈值」，除非逐条核验原文用途和适用条件。
- 不把水深乘速度的安全评估指标直接改写成普适噪点过滤规则。
- 不写「Priority-Flood 不会制造平坦面」。填洼后仍需检查平坦面和水力连通性。
- 不写「红壤地区初期必然吸收 30–50 mm」。该范围只能作为待试验假设。
- 不写「过滤率达到 90% 即证明模型正确」。过滤率只能是展示质控指标。

### 8. 既有不合规展示层退役

- `scen_free_100m_dt2p5_sv6h_realdem_cleaned` **判定为不合规展示层**，理由三条：写死 4/9 像元阈值；写死 100 m 单元面积；声称「ARR 2019 规定」。
- 该层**由 `display_qc` 取代，不得作为默认生产层或默认展示层**。它可保留为历史证据，但必须标注为不合规、不得对外作为成果展示。
- 该层实测改动量登记为本 ADR 的否决依据：`res.max` 湿面积 −36.56%、水量 −53.16%。如此量级的未登记改动，属计划 §2.3 与 §8 风险表「滤波误删真实积水（高）」的实际发生。
- 该层含 `results/res.mass`（与源 run 逐位相同）且含 `run.log`，会被 `g15_mass_recheck.py` 计为独立 run。现已按第 4 条加入派生层判定，并在 `mass_recheck_g15.json` 的 `excluded_variants` 登记为「展示派生层（非独立模型 run）；含复制自源 run 的 res.mass，按 ADR-0010 第 8 条不参与质量门计数」。质量门计数不再需要人工排除。

## 后果

### 正面后果

- 分辨率口径单一化：200 m 生产、100 m 敏感性，跨分辨率比较强制走同一物理面积阈值，杜绝 4 倍面积误判。
- 展示层可回滚、可追溯、可复现：派生标记齐全，raw 哈希不变，参数哈希可复核，`display_qc` 与 raw 可一键切换。
- 地形改动分层可控：`DEM_HYDRO` 与 `DEM_HYDRAULIC` 分离，防止填洼或刻蚀被静默带入求解。
- 质量门口径唯一：`FAIL-EXPLAINED` 不计通过，消除「全量通过」这类不可复核表述。
- 阈值跨分辨率可复现：换算公式固定，100 m 与 200 m 结果可由同一套 km² 阈值重新推导。

### 负面后果与限制

- **200 m 分辨率本身的能力上限未解除。** 200 m 相对 100 m 湿面积少 7.83 km²（−2.97%），站址像元水深 0.008 m、±2 格 0.547 m；站址邻域水深对分辨率敏感。方案 B 未批准前，本 ADR 不改善物理精度，只改善口径与观感。
- **`display_qc` 不改变物理结果。** 它带 `not_physical_recalculation=true`，只能作为展示层；不得用于任何物理结论、验证指标或资产级判据。
- **退水异常未消除。** 无排水网络与 FREE 缓排导致的退水期面积不降反增（+27.68 km²）在 Phase 4 授权资料到位前仍然存在；本 ADR 只禁止以滤波掩盖。
- **地形层资料缺口未闭合。** `DEM_REPAIRED` 的局部修复依据与 `DEM_HYDRAULIC` 的结构修改清单仍受 G7 垂直基准与业务资料阻塞。
- **久隆独立验证仍为 `WEAK/未测`。** CSI、POD、FAR、NSE、R²、水深误差不构成硬门。
- **默认展示层已回退 raw，`display_qc` 尚未接入前端。** 退役 `_cleaned` 后，`flood_visualization/configs/cases/jiulong.yaml` 已把 `default_run_id` 改为 `scen_free_200m_sv6h`（200 m 生产基线 raw），`_cleaned` 从 `runs` 移除并加退役注释，100 m 标 `role: legacy`。`display_qc` 三档虽已产出，但**未接入前端**：按计划 §9.3 第 3 条，`display_qc` 是否作默认展示层须用户确认。在确认前，前端只能看 raw 层。

### 需要用户确认的事项（计划 §9.3）

1. **推荐：** 先按 200 m 生产基线完成 Phase 0 和展示治理；100 m 仅作为敏感性对照。
2. 是否批准 100 m 或更细分辨率的完整物理重跑；批准前不把 100 m 结果升级为生产基线。
3. 是否允许使用 `display_qc` 作为前端默认展示层；raw 保留为科研诊断层。
4. 是否能提供站址坐标、排水网络、潮位/水位和事件窗口观测资料。
5. 是否接受当前久隆独立验证状态为 `WEAK/未测`，不设置 NSE、R² 和水深误差硬门。

## 替代方案

| 方案 | 内容 | 不采纳理由 |
|---|---|---|
| 方案 B：先批准 100 m 或更细重跑再治理 | 完成新分辨率质量门与分辨率收敛后冻结 100 m 阈值 | 需用户单独批准、需计算资源、需输入可信度；当前目标是快速改善现有交付产品。保留为后续升级路径，不废止 |
| 沿用 `_cleaned` 的 4/9 像元规则 | 保持现有展示层 | 写死像元数与 100 m 面积，200 m 上等价阈值放大 4 倍；声称未核验的规范依据；实测面积 −36.56%、水量 −53.16% 且未登记 |
| 只做视觉平滑，不做斑块统计 | 用渲染手段消除噪点 | 不可审计、不可复现、不可回滚；无法区分「删掉噪点」与「删掉真实积水」 |
| 直接把 `DEM_HYDRO` 当作求解地形 | 用填洼后地形重跑 | 会抹除真实洼地，改变蓄水容量与流向；违反四层契约 |
