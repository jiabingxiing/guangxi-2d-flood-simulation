# ADR-0008：模型定版与桥涵结构使用限制

- **状态**：已接受（Accepted）
- **日期**：2026-10-27
- **触发**：B8b 发现 T016c 桥洞算例在本构建 8.1.0 与仓库自带 5.7.0 参考可执行文件下结果不一致（`docs/stage2_benchmarks.md` §6.1），终稿 十六 要求以 ADR 锁定模型版本。

## 背景

- 生产构建：LISFLOOD-FP 8.1.0（MinGW/w64devkit GCC 16.2，含 `_WIN32` 对齐分配补丁），SHA-256 `651306080e20529dc6a72c8113037a4333c943c7d6adad712457d41f4d321ee8`（`data/catalog/input_manifest.json` 键 `lisflood_exe`）。
- 仓库源码包自带 5.7.0 参考可执行文件；T016c（桥洞-堰官方算例）双构建对照：5.7.0 逐位复现仓库参考 `res.stage`（证明输入与运行方式一致），8.1.0 的 chan 全站系统偏差 −0.181 m，且 bridge/orifice 组下游完全阻断（水深 0，桥面以上仍有约 4 m 水，物理不合理）。
- B8a 合成堤防四组在本构建全部通过：DEM 加高（wall 封闭零越堤/零出流）、开口（notch 0.86×）、`weirfile` 堰（0.53×），E_mass < 1e-3。

## 决策

1. **生产模型定版为 8.1.0 自构建**（`acceleration` 求解器 + 固定 `initial_tstep` + `res.mass` 全程 E_mass 监控）。5.7.0 仅作基准交叉复核用途，不进入生产。
2. **结构物表达只允许两种方式**：DEM 加高（含开口低槛）与 `weirfile` 堰式链接（B8a 已验证）。**禁止使用 bridge/orifice 型链接（`eb/wb/nb/sb` 标签）**进入任何生产或对外交付运行，直至完成下述再验证。
3. **bridge/orifice 路径再验证条件**：升级版本或修改构建后，须重跑 T016c 双构建对照，满足「与 5.7.0 参考差异在声明容差内 + 下游过流物理合理」两条，方可解禁；结果记入阶段 2 报告。
4. **chan 系统 −0.181 m 偏差登记为已知构建差异**：不影响本降级模式三案例（三案例均不含 chan/桥涵结构，边界为 FREE/HFIX/HVAR + 点源 Q）；生产事件报告须继续附 E_mass 账目（终稿 13.2），超门限按 FAIL-EXPLAINED/FAIL 口径明示。
5. **重跑范围**：既有全部生产 run 未使用 bridge/orifice 结构，本决策不触发任何历史 run 重跑；约束自本 ADR 起生效。

## 后果

- B8 维持 **PASS_PARTIAL**：连通性可表达（B8a），桥涵路径未获独立验证（B8b）。禁止表述「结构物建模已通过验证」「桥涵能力已验证」。
- 真实堤防/桥涵/站门建模继续受 R1 资料缺口阻塞；取得资料后按本 ADR 第 2 条方式实现（加高/堰），不使用 bridge 型。
- 若未来业务要求涵洞/闸门水力学表达而 weir/加高不足以近似，须走第 3 条再验证或更换经独立验证的模型版本，不得静默使用未验证路径。
