# ADR-0025：三案例管网耦合物理重跑的隔离算例与对照基线口径

- **状态**：已接受（Accepted）。
- **日期**：2026-11-25。
- **触发**：ADR-0024 决策 3 选定「城区点汇 + 河道排口正源」为生产推荐方案，但此前只有
  `not_physical_recalculation=true` 的诊断投影，从未真正调用 `lisflood.exe` 跑过管网耦合。
  执行 `plans/pipenet_3cases_coupled_rerun_plan.md` 时暴露三项口径问题，需在跑之前定案。
- **关联**：ADR-0004（公开数据降级）、ADR-0006（PASS ≠ 预测正确）、ADR-0010 第 8 条
  （派生层不计 run）、ADR-0020（SGC 河道耦合）、ADR-0024（PipeNetGen 与耦合方案）。

## 背景：执行前核实出的三项事实

计划中的若干假设经源码与数据核实后需修正。这些修正直接决定本节的三条决策。

1. **SGC 的 OpenMP 竞争不存在。** 计划引用的 `iterateq.cpp:496` 是死代码
   （`iterateq.cpp:118-141` 的 SGC 分支整段被注释，只执行
   `printf("SGC not processed here")`）。真实 SGC 路径为 `lisflood.cpp:766` →
   `Fast_MainStart` → `Fast_MainInit` → `lisflood2/sgm_fast.cpp`，点源插值位于
   `sgm_fast.cpp:3696-3710` 的 `#pragma omp single` 串行区，源码注释为
   *"prevent any threading issues if a TimeSeries is used on multiple points"*。
2. **排口落格与城区点汇格 100% 重叠。** 贵港 41/41、久隆 41/41、宁明 44/44。
   但求解器允许 sink 与 source 是不同 `P` 行、落不同像元，故正确处置是
   **注入点 BFS 移位**，而非删除重叠格（删除会丢失该城区排涝能力）。
3. **SGC 模式下非零 `QVAR` 引入同量级体积残差。** 单变量实测（30×30 微型 SGC 网格，
   雨量 337 440 m³）：`QVAR` 恒为零 → E_mass = 0.0；`-0.0086806 m³/s` → 残差
   +1103.9 m³；`+0.0086806` → +126.1 m³；成对 ±→ +1100 m³。纯降雨无点源 → 0.0。
   注入点落在河道行或洪泛平原行**不改变**该残差，故与落点无关。

## 决策

### 1. 宁明改为「自产基线 + 耦合」双算例，均置于 `outputs/pipenet/ningming/`

原计划取 `scen_q6000_n100_100m_choff_eclosed` 作宁明对照基线，但该 run 的 `meta.json`
自带 `diagnostic_only: true` 与 `must_not_be_used_as: "结果基线、验证样本、业务结论"`。
其替代候选 `scen_q6000_n100_100m` 保留了已被该诊断 run 证伪的东缘 FREE 出流短路缺陷，
用它作基线比用诊断 run 更糟。

因此宁明在 `outputs/pipenet/ningming/` 内**自产一对同构算例**：`run_baseline_*` 与
`run_coupled_*`。二者共享同一 `dem.asc`、`rain.rain`、时间轴、时步与边界定义，
唯一变量是管网点源项。

**验收证据**：自产基线 `run_baseline_c100m` 的 E_mass = 1.032e-4，与原
`choff_eclosed` 的 0.0001032 **完全一致**，证明装配忠实复现了原边界定义（东缘关闭），
未引入数值偏差。

### 2. 三案例统一采用自产基线，历史 run 只作为装配来源

贵港与久隆虽无 `diagnostic_only` 标注，也同样自产基线。理由：对照关系自洽
（同目录、同批次、同代码哈希），且不动任何历史 run 的状态标注。

### 3. 质量门隔离靠 `CASE_ROOTS` 白名单，不靠「目录内无 res.mass」

`g15_mass_recheck.py` 用显式三案例根白名单
（`outputs/{ningming,jiulong,guigang}`），不递归扫描 `outputs/`。
`outputs/pipenet/` 因此天然在扫描之外。

**不采纳**「在 g15 里加 pipenet 排除规则」：那会把白名单退化为黑名单，
将来每新增一个案例根都要改 g15，且失去「白名单即契约」的可审计性。

回归测试 `tests/regression/test_mass_recheck_g15.py` 锁定的是**机制**而非目录内容：
早先版本断言「`outputs/pipenet` 下不存在任何 `res.mass`」，该断言会被本 ADR 的
正确产物触发，已改为断言 `pipenet` 不在三案例根内、且 `CASE_ROOTS` 恰为三项白名单。

### 4. 单格抽取量上限：`safety_factor`，不是管径能力

抽取量 = `min(单格管网能力, safety_factor × 瞬时净雨)`，`safety_factor = 0.85`。

经核算，`capacity_cap_mmh = 80` 在三案例**均未生效**：雨率峰值分别 14.10 / 10.60 /
4.55 mm/h，`0.85 × 峰值` 为 11.98 / 9.01 / 3.87 mm/h，全部远低于 80。真正约束结果的是
`safety_factor`，它为保证零负水深的**数值安全系数**，不是管径水力标定值。

因此所有削减百分比必须读作「85% 净雨可排假设下的排涝上限效应」，不是管网真实潜力。
实现中以 `capacity_cap_effective` / `cap_truncated_cells` / `cap_binding_cells` 三字段
随结果一同输出，使结论自带适用范围。

## 后果

- 三案例获得可复算的物理耦合结果，`physical_recalculation=true`，
  与既有 `not_physical_recalculation=true` 的诊断层明确区分。
- `outputs/pipenet/` 承载带 `res.mass` 的算例，但质量门 SSOT 保持 66 PASS /
  4 FAIL-EXPLAINED / 0 FAIL 不变（白名单机制）。
- **SGC 路径的限制必须随结论披露**：久隆生产算例 E_mass=7.7e-6 通过，是因为管网
  点源通量相对全域降雨/来水极小；若将来提高久隆抽取强度，残差会按第 3 项事实放大。
  该限制已在 `drainage_kernel.py` 的 `build_fullgrid_coupled_forcing` 文档与
  `tests/integration/test_coupling_pipeline.py::test_sgc_qvar_smoke` 中留痕。
- 计划原文中「`4,032` 格量化为 8–10 个分档曲线以避免运行时间暴涨」被保留，
  但分档改为**容量值域等分**（原案为分位数）：逐格能力在 80 mm/h 处有大原子
  （贵港 2808/4032），分位数会压成 2–3 档，档内跨度达数十 mm/h。
