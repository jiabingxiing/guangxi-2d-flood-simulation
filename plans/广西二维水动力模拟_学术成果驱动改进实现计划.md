# 广西二维水动力模拟学术成果驱动改进实现计划

## 1. 项目概述与目标

### 1.1 背景与问题

项目当前为公开数据降级模式情景级（ADR-0004）。质量门 61 PASS / 3 FAIL-EXPLAINED / 0 FAIL（64 run，权威值 `2d_hydro_project/data/catalog/mass_recheck_g15.json`，2026-11-16 复算）。水量闭合已全量受控，但预测性验证与驱动链存在五个明确短板：

| 编号 | 短板 | 事实证据 |
|---|---|---|
| P1 | 上游来水无产汇流物理 | 贵港郁江入流为手工三角过程线（`yujiang.bdy` 10→115→20 m³/s）；宁明为 Q 档位情景；久隆无上游来水 |
| P2 | 降雨驱动单一且平滑 | 仅 ERA5 锚点逐时均匀雨；IMERG 只做交叉校验未做驱动对比 |
| P3 | 垂直基准未闭合（G7） | 贵港站 43.09/44.00 m 与模型 apparent offset +21.17/+24.00 m 两时点不一致，不得作 datum_offset（`scripts/stage6/validate_guigang_s1.py`） |
| P4 | 虚警偏高、成因未产品化 | 贵港 baseline_realdem FAR 0.921 / CSI 0.076；无雨 run FAR 0.817 证明滩地降雨积水主导，但未形成归因产品 |
| P5 | 无概率/不确定性框架 | 宁明 9 run 集合（CSI 0.28–0.47）仅作枚举，无超越概率表达；Copula/信息扩散方法空白 |

两位教授的成果（来源 `教授交流/教授检索详情.txt`）与上述短板一一对应：吴欢体系解决「水从哪里来、误差怎么传」（DRIVE 产汇流、MMF 误差传播、IHC 初始状态、DRIVE-Urban 成因分解）；钟鸣体系解决「水来了多危险、怎么决策」（FAT 到达时间、Copula 联合阈值、ICESat-2 基准核证、电网暴露层）。本计划把两套体系降级落地为本项目可执行、可验收的改进包。

### 1.2 目标用户与场景

- 用户：本项目维护者（AI 代理执行 + 用户审批）；下游场景为电网洪涝研究（变电站站址暴露分析）。
- 一次调用的输入输出：输入为既有 run 目录（`results/res*.wd` 6 h 帧）+ 新数据源（IMERG、GloFAS、ATL13、GSW）；输出为新产品 GeoTIFF/JSON/CSV 与审计件（落 `data/catalog/`），全部为研究性/情景性产物。

### 1.4 范围外

- 阶段 6 在线业务化（滚动预报、容错、SLA）——维持不做（ADR-0004：不是业务预警系统）。
- 真实排水管网建模（D1–D5 资料缺）、贵港 5 m 站区模型（待测绘资料）、喀斯特物理建模。
- SWMM 耦合、CaMa-Flood 全局运行、滑坡—堰塞湖灾害链、LSTM 流量混合模型、社区韧性 FDM/ANP（理由见 2.5）。
- 修改 `models/` 上游源码；重跑未列入 5.3 授权清单的任何 run。

### 1.5 假设与前置约束

- 授权：本计划经批准后，5.3 节 run 清单视为已授权（用户 2026-11-22 决定），实施期不再逐项请求批准；清单外 run 仍须单独批准。
- 环境：统一 uv（阿里云镜像已全局配置）；运行 Python 前设 `PYTHONUTF8=1`；父子工程 `.venv` 不手工搬移。
- 硬约束：已有 `res.mass` 的 run 目录禁止覆盖（写入前走 `scripts/common/grid_io.guard_no_overwrite`）；派生层目录不得含 `res.mass`；floodviz 只读父项目；新展示层沿用 `display_qc` 命名与派生标记。
- 证据纪律：新方法开工前先立 ADR-0015~0018 预注册；未验证指标写「未测/未验证」；FAIL-EXPLAINED 不计通过；PASS ≠ 预测正确。
- 算力：桌面机（8C/16T，16 GB 内存）；无新增硬件预算。

### 2.4 组合结论

- 直接复用：LISFLOOD-FP 8.1.0（本地已集成）、净雨预处理器（Green-Ampt 链）、`channel_engine`/`net_rain`/`patch_analysis` 共用底座、make_products 产品口径、floodviz 发布链——全部不动。
- 新引工具：仅 3 个轻量数据工具（上表）。均为数据获取/统计拟合件，不触碰求解器。
- 自研：GR4J 型集总产汇流（约 200 行，标准 4 参数 + 无雪模块，引 Perrin et al. 2003, JH 279，出处同 2.1 复核流程）；FAT/归因/概率后处理（复用 `patch_analysis` numpy 风格，不引 scipy/skimage）。理由：无实测流量，重型水文框架（VIC/CaMa-Flood/HEC-HMS）收益为零且违反降级纪律。

### 3.4 关键算法设计

**A1 GR4J 型集总产汇流（P1，服务 S3）**
- 输入：流域面平均日雨（ERA5 格点聚合）、GA 预处理器日蒸散代理与土壤湿度序列。
- 方法：标准 GR4J 四参数（生产库 X1、交换系数 X2、汇流库 X3、单位线基流时间 X4），无雪模块；参数取文献通用区间中值，不做自动率定，对 X1/X3/X4 各三档敏感性。
- 初始水文条件（IHC，吴欢 S2S 教训）：生产库初始蓄水比例 S_init/S1 = θ_mean/θ_s（GA 预处理器网格均值），映射规则预注册进 priors JSON。
- 日→时分配：逐时等分并按日水量守恒。
- 验证：与 GloFAS 郁江/明江格点日流量对比（先验对照，不作拟合目标，防循环论证）；r ≥ 0.7 为达标，未达记「未验证」。
- 产出：`inflow_guigang.bdy`、`inflow_ningming.bdy` + `inflow_audit.json`。
- 数据前提：郁江贵港断面控制面积、明江宁明断面控制面积——当前未确认；确认方法为公开流域概要/水文年鉴核验后写入 priors JSON，写入前不得开工 A1 的边界生成。

**A2 MMF 降雨多源评估（P1 准备 / P2 评估，服务 S4）**
- 协议（吴欢 2017/2021）：同一模型、同一净雨链、同一验证景，仅替换降雨驱动；评「洪水响应差异」而非「雨量差异」。
- 报告三段：面雨量偏差 → 湿面积/CSI 传播比 → S1 POD/FAR/CSI 差异表。
- 前提：IMERG 2024-09 窗口可下载（GES DISC 抽样核验）。

**A3 FAT/超阈时间产品（P0，服务 S1）**
- 定义：首湿时刻 = 该像元首次 wd>0.05 m 的模型时刻；超阈时刻 = 首次 wd>情景阈值；超阈历时 = 累计超阈帧时数。情景阈值 0.3/0.5/1.0 m 三档，输出分别独立成件。
- 站点表：站址像元 ±2 格（ADR-0006 口径）；站址像元未湿时报 NA 并附最近湿像元距离（久隆站址像元 0.008 m 几乎不湿，先例在案）。
- 三级窗（钟鸣 2025 FAT 思想）：按超阈时刻相对事件起点分组展示（<6 h / 6–24 h / >24 h），标注「研究性分组，非应急等级」。

**A4 成因归因产品（P0，服务 S2）**
- 规则预注册：event-max 湿像元集合上，full run 湿 ∧ rain_off run 湿 → river-origin；full 湿 ∧ rain_off 干 → pluvial-origin；full 干 ∧ rain_off 湿 → disagreement（水量再分配，单独统计）；边界 1 格环带单独标记。
- 依据：吴欢 DRIVE-Urban 双成因思想 + 贵港既有无雨 run（FAR 0.817）差分可行性已在 ADR-0013 证实。
- 产出：`origin_class.tif` + `genesis_rules.json`（先冻结后计算）。

**A5 ICESat-2/GSW 基准核证探针（P1，服务 S5）**
- 方法：icepyx 检索郁江/明江 bbox 内 ATL13 轨（2019–2026），取水面段高程（质量标志过滤）；与 dem.asc 河道格网高程求差。
- 口径：输出「DEM 表面—ATL13 水面系统差」区间（中位数 ± IQR、分轨明细），并明确局限：该差含水深与基准差两个分量，G7 只能收到「有界估计」，不得写死 datum_offset 常数（ADR-0004 红线维持）。
- GSW occurrence（≥80% 常水像元）用于圈定河道/常水区掩膜；坡度校正（钟鸣 2026）在沿程坡降明显的明江河段可选做。
- 覆盖不足（<10 轨）时如实降级为「覆盖不足」并在报告登记。

**A6 集合超越概率 + Copula 联合阈值探索（P2，服务 S6）**
- 集合→概率：宁明 9 run（3Q×3n×3 阈值口径）+ 贵港敏感性集，逐像元 P(wet|ensemble) 图；成员清单与质量门状态强制入审计 JSON。
- Copula：变量 = 区域年最大 3 日雨量（ERA5 1979–2025 事件样本）× 事件前 30 日湿度代理；边缘分布 + Gaussian/Clayton/t 三族 AIC 选优；给出「雨量×前期湿度」联合重现期曲面，对照情景矩阵取值。
- 红线：统计阈值仅用于情景设计参考，禁业务告警（ADR-0004）；样本不足用信息扩散（钟鸣 2019）+ 参数 Bootstrap 置信区间；拟合失败如实记「未验证」。

### 6.2 标注与证据登记

本项目无人工标注任务。「标注」指 run 与产品的证据登记：每个新产品写 `data/catalog/*.json` 审计件，含输入哈希、脚本版本、E1–E4 证据等级、`not_physical_recalculation` 类派生标记（展示层）、以及显式「未验证」字段；媒体水位常数（贵港 43.09/44.00 m）维持「公开报道、站基面、G7 未闭合」标注，不升级。

### 6.3 划分与防泄漏

- 划分：验证切片按事件时刻划分（ADR-0006 切片口径）；开发用帧与验证用景分离。
- 防泄漏规则：宁明 9 run 的参数扫描不得用 GF-3 主帧（8/24）选优后再用同帧报告；选优用灾前帧，报告用主帧。GloFAS 只作先验对照、不作拟合目标，防止循环论证。贵港 IMERG/GR4G run 的 S1 评估与历史 plan_acceptance 使用同一足迹口径，保证可比。
- 河段级留出：ATL13 探针的分轨结果中随机保留 ≥2 轨不参与任何调参，仅作独立复核。

### 6.4 数据不够时的降级策略

- IMERG/GloFAS/ATL13 任一不可得：对应任务记「数据不可得」，不留半成品；S3/S4/S5 记「未验证」。
- 无实测流量：GR4J 不做率定，只做三档敏感性（E3 情景级）；r 达标只证明与再分析先验一致，不证明真值。
- 业务授权数据（Q/Z/断面/雨量）持续缺位：维持降级模式，全部新能力标 E3；一旦到位按 ADR-0004 流程升级证据等级。

### 6.5 评估协议与训练策略

- 评估协议：复用 ADR-0006 产品口径（湿判据 0.05 m、切片、站址 ±2 格）与 `guigang_scenario.py::verify()` 指标定义；阈值扫描增加历时维度（吴欢 2012 设计）。
- 训练策略：本项目无深度学习训练。GR4J 参数不做自动率定（无观测目标）；只做 X1/X3/X4 三档枚举敏感性。若后续获得业务流量资料，再按 ADR 新立率定项。
