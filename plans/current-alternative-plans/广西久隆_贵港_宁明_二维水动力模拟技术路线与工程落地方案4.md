# 审阅意见：广西久隆、贵港、宁明精细二维水动力洪涝模拟推演方案

总体评价：方案架构完整，技术路线分级合理，"尺度解耦 + 纯CPU + SAR对账 + DEM水文校正"四大准则方向正确。但经逐节审查，发现 **1 处代码级致命错误、2 处坐标系统错误、若干工程完整性缺口与多项可完善的风险点**，现逐项列出并给出修改建议，部分附修正代码。

---

## 一、致命问题（必须修复后方可进入试算）

### 1.1 局部惯性波求解器 **y 方向通量从未计算**（第七节 `local_inertia_engine.py`）

`update_flux_local_inertia` 函数签名返回 `(new_qx, new_qy)`，但函数体内只写了对 `j` 方向（x 向相邻列）的循环，`new_qy` 自始至终为全零数组、从未被赋值。这意味着**模型在南北方向上完全不产生动量通量，洪水只能沿东西向传播**，久隆/宁明这类地形起伏、河道走向复杂的区域会出现系统性错误的淹没形态，且这种错误在水量守恒检验中unable被发现（因为质量仍然守恒，只是流向错误），极具隐蔽性，必须作为 P0 级缺陷修复。

**修复建议**：补充对称的 y 方向循环（或采用统一的 `for direction in (0, 1)` 向量化写法），示例：

```python
@njit(parallel=True, fastmath=True)
def update_flux_local_inertia(h, z, qx, qy, n_mat, dx, dy, dt, h_dry: float = 1e-3):
    rows, cols = h.shape
    new_qx = np.zeros_like(qx)
    new_qy = np.zeros_like(qy)

    # --- x 方向通量（原逻辑保留）---
    for i in prange(rows):
        for j in range(cols - 1):
            h_L, h_R = h[i, j], h[i, j + 1]
            if h_L < h_dry and h_R < h_dry:
                continue
            eta_L, eta_R = z[i, j] + h_L, z[i, j + 1] + h_R
            h_flow = max(eta_L, eta_R) - max(z[i, j], z[i, j + 1])
            if h_flow <= h_dry:
                continue
            slope = (eta_L - eta_R) / dx
            q_old = qx[i, j]
            n = 0.5 * (n_mat[i, j] + n_mat[i, j + 1])
            denom = 1.0 + dt * GRAVITY * (n**2) * abs(q_old) / (h_flow**(7.0/3.0))
            new_qx[i, j] = (q_old + GRAVITY * h_flow * dt * slope) / denom

    # --- y 方向通量（补全，原代码遗漏）---
    for i in prange(rows - 1):
        for j in range(cols):
            h_T, h_B = h[i, j], h[i + 1, j]
            if h_T < h_dry and h_B < h_dry:
                continue
            eta_T, eta_B = z[i, j] + h_T, z[i + 1, j] + h_B
            h_flow = max(eta_T, eta_B) - max(z[i, j], z[i + 1, j])
            if h_flow <= h_dry:
                continue
            slope = (eta_T - eta_B) / dy
            q_old = qy[i, j]
            n = 0.5 * (n_mat[i, j] + n_mat[i + 1, j])
            denom = 1.0 + dt * GRAVITY * (n**2) * abs(q_old) / (h_flow**(7.0/3.0))
            new_qy[i, j] = (q_old + GRAVITY * h_flow * dt * slope) / denom

    return new_qx, new_qy
```

同时该引擎**缺少自适应 CFL 步长计算函数**，而局部惯性格式的 CPU 效率优势恰恰来自宽松但仍需满足稳定性条件的自适应 `dt`（de Almeida et al., 2012 的 `αdx/√(gh_max)` 判据）。当前代码把 `dt` 作为外部传入的固定参数，若用户不了解该判据极易设置过大步长导致数值振荡或过小步长丧失 CPU 优势，建议补充：

```python
def compute_adaptive_timestep(h: np.ndarray, dx: float, dy: float, alpha: float = 0.7) -> float:
    """de Almeida (2012) 自适应局部惯性波稳定时间步长"""
    h_max = np.max(h)
    if h_max <= 1e-6:
        return 1.0  # 全域干床时给定保底步长
    return alpha * min(dx, dy) / np.sqrt(GRAVITY * h_max)
```

并作为 `model_runner.py` 主循环中每步必调用的稳定性闸门，同时建议在 `8.2 核心质量验收门禁`中**新增第三道门禁——CFL 稳定性门禁**（当前只有水量守恒与 SAR 对账两道）。

## 二、坐标系统错误

- `configs/cases/guigang.yaml` 标注 **EPSG:32648（UTM 48N）**，但贵港市经度范围约 109.3°–110.5°E，落在 **UTM 49N（108°E–114°E）**范围内，应为 **EPSG:32649**。
- 宁明（约 106.8°–107.3°E，UTM 48N）与久隆（约108.6°E，UTM 49N）的标注经核实无误。

建议在 `data_manifest.json` 中为三个案例分别加入经纬度包络框自动校验脚本（基于 `pyproj.database.query_utm_crs_info` 自动反查推荐 EPSG），避免人工标注再次出错。

## 三、工程完整性缺口

### 3.1 关键缺失：未锚定具体历史暴雨洪涝事件 ★★★（最高优先级）

全文反复提及"SAR 真值对账""实测水文站驱动""灾中灾后对比"，但**全文没有给出任何一场具体历史洪涝事件的日期、重现期、对应卫星过境时间表**。没有锚定具体事件，第二、三节的降雨驱动、边界条件提取、SAR 对账全部无法落地执行。强烈建议在第八节前增补 **"历史洪涝事件选取表"**，至少包含：

| 案例 | 候选历史事件（日期） | 对应重现期 | 水文站同期记录 | 可用 Sentinel-1/GF-3 过境清单 |
|---|---|---|---|---|
| 久隆 | 待定（建议筛选近 3 年台风伴生暴雨过程） | - | - | - |
| 宁明 | 待定（建议筛选明江漫滩历史场次） | - | - | - |
| 贵港 | 待定（建议筛选郁江干流超警戒场次） | - | - | - |

并明确：**若目标事件洪峰期恰好缺少 SAR 过境（Sentinel-1 重访周期 6~12 天，常规极轨卫星存在"错峰"风险），则退化验证策略**（例如改用退水期影像反推、或启用多源 SAR 融合 GF-3 补点）需提前预案，而非等到执行阶段才发现"无真值可用"。

### 3.2 下载脚本"标题与实现数量不符"

第二节标题宣称"4 类关键输入数据均可自动下载"，但 2.2 节只给出了 **ESA WorldCover** 与 **ERA5(Open-Meteo)** 两类实现，DEM（Copernicus GLO-30/ASF）与 SAR（ASF Vertex / asf_search）的自动下载代码缺失，而 `pyproject` 依赖中已包含 `asf-search`、`pystac-client`、`planetary-computer`，说明是遗漏而非有意裁剪。建议补全，示例骨架：

```python
import asf_search as asf

def download_sentinel1_grd(aoi_wkt: str, start: str, end: str, out_dir: Path) -> list[Path]:
    """基于 AOI 与时间窗检索并下载 Sentinel-1 GRD（需注册 Copernicus Dataspace 账号与 .netrc 凭证）"""
    results = asf.geo_search(
        platform=[asf.PLATFORM.SENTINEL1],
        intersectsWith=aoi_wkt,
        start=start, end=end,
        processingLevel=[asf.PRODUCT_TYPE.GRD_HD],
    )
    out_dir.mkdir(parents=True, exist_ok=True)
    return [Path(r.download(path=str(out_dir))) for r in results]
```

同时需**明确澄清认证边界**：WorldCover/ERA5 确为匿名免认证，但 Copernicus Dataspace（DEM/SAR）必须注册账号并配置 `.netrc`/token，不能笼统宣传"全自动免认证拉取"，避免现场执行人员因认证问题卡壳。

### 3.3 DEM 水文校正流水线"四步法"实际只实现了一步

第四节文字描述了四步（滤波去噪→填洼→河道刻蚀→建筑物刻蚀），但代码只给出了 `burn_stream_bathymetry`（第 3 步），**填洼（Priority-Flood Fill Sinks）与建筑物/堤防刻蚀均无代码**，且当前刻蚀方式是"矢量缓冲区内整体下挖固定深度"，并非标准 AGREE 算法（AGREE 需要先大幅拔高非河道缓冲区再平滑重建纵剖面，以避免出现突变陡坎导致数值不稳定）。建议：

1. 引入 `richdem` 或 `pysheds` 实现标准 Priority-Flood 填洼：
```python
import richdem as rd

def fill_sinks_priority_flood(dem_path: Path, output_path: Path, epsilon: bool = True) -> None:
    dem = rd.LoadGDAL(str(dem_path))
    rd.FillDepressions(dem, epsilon=epsilon, in_place=True)
    rd.SaveGDAL(str(output_path), dem)
```
2. 补充堤防/围墙"拔高"刻蚀函数（与河道下挖方向相反），并在久隆案例中重点应用于变电站围墙/地坪——这是第一阶段明确提出的核心验证目标（"变电站地坪反倒灌阻水"），当前代码完全没有实现该功能，与阶段验收目标直接脱节，需优先补齐。
3. `burn_depth_meters=4.0` 不应作为全域统一默认值，久隆小微冲沟、宁明明江、贵港郁江干流的天然河槽水深量级相差可达一个数量级，必须从 `configs/cases/*.yaml` 按河道等级分段读取，而非硬编码默认参数。

### 3.4 入渗参数"声明输入但从未进入求解器"

数据清单第 5 项明确要求水文土壤分组（HSG）/饱和导水率作为输入，但 `update_depth_mass_balance` 的质量方程中只有 `rainfall_rate` 一项净输入，完全没有扣除入渗损失。对于时长可达 72 小时的长历时暴雨过程，尤其是宁明喀斯特地貌（岩溶地区入渗/伏流机制复杂，这一点在方案中甚至完全未被提及），忽略入渗会显著高估地表产流总量。建议在连续性方程中增加入渗损失项（哪怕先用简化的 Green-Ampt 或分 HSG 等效损失率，而非真正耦合复杂岩溶水文模型）：

```python
h_candidate = h[i, j] + dt * (div + rainfall_rate - infiltration_rate[i, j])
```

并在文字部分明确标注：**喀斯特地区（宁明）的入渗/落水洞/地下河效应超出常规 Green-Ampt 模型能力范围，建议作为单独的"模型适用性风险"在第八节中列明，而非与贵港平原区同等对待**。

### 3.5 曼宁糙率码表遗漏近海典型地类

久隆被定位为"近海低丘小流域"，ESA WorldCover 分类码中 **95（红树林 Mangroves）** 对沿海滩涂区极为常见、且其糙率显著高于普通湿地（建议 n≈0.15~0.20），当前 `LULC_TO_MANNING` 字典遗漏该码，也遗漏了 70（雪/冰，虽广西基本不适用可不补）与 100（苔藓地衣，低优先级）。建议至少补全 95。

### 3.6 嵌套网格（Nested Grid）技术路径存疑

第三阶段核心卖点是贵港"Nested Grid 实战"，但第三节选型结论明确锁定 **LISFLOOD-FP（结构化笛卡尔均匀网格）** 为主力引擎。标准 LISFLOOD-FP **并不原生支持变分辨率嵌套网格**（不同于 HEC-RAS 2D 的非结构网格可局部加密），若要实现"30m + 5m 嵌套"，实际可行路径只有：
- (a) 改用 HEC-RAS 2D 作为贵港阶段主力（与前两阶段引擎不一致，需要额外做跨引擎一致性验证）；
- (b) 采用 LISFLOOD-FP 多个独立分辨率子域 + 自行编写边界通量交换脚本做"伪嵌套"（松耦合，非真正意义 Nested Grid，且存在质量守恒跨界误差风险）；
- (c) 引入支持真正多级嵌套的其他开源引擎（如 ANUGA 或自行实现 Quadtree 自适应网格，但会违背"纯CPU轻量"初衷）。

当前方案**没有在技术路线中明确三选一的具体决策与理由**，这是第三阶段能否如期落地的核心技术风险，建议在第三节或第八节补充专门的技术决策说明，并补做小规模原型验证（久隆/宁明阶段可预留"单域+加密子域"的最小可行性试验，而非留到贵港阶段才第一次验证嵌套架构）。

### 3.7 SAR 数据预处理与过境时效风险未闭环

- SAR 影像在做水体二值化前通常需要 **相干斑点噪声滤波（如 Lee/Refined Lee Filter）+ 阈值分割（Otsu 或双阈值法）**，当前 `sar_validation.py` 直接假设输入已是"水体二值图"，但第一节数据源仅给出 GRD 原始影像下载地址，中间的"SAR→二值水体掩膜"处理步骤完全空白，建议在 `src/preprocessing/` 下补充 `sar_water_extraction.py`。
- 极轨卫星重访周期（Sentinel-1 约 6~12 天）与洪峰历时（数十小时量级）严重不匹配的风险在第五节只字未提，建议明确：若无法捕获洪峰时刻影像，验证策略退化为"退水期/位涨期淹没范围包络对比"，并在 CSI 验收目标上做相应说明（允许适度降低期望值或改用更宽松的时间窗口）。

### 3.8 降雨输入精度风险

Open-Meteo Archive 接口底层为 ERA5/ERA5-Land 再分析数据，水平分辨率约 9~31km，**对流性强降雨峰值的系统性低估是公认问题**，尤其广西夏季暴雨多为中小尺度对流系统主导，直接使用再分析场驱动可能导致洪峰流量显著偏小。建议：
1. 增加与广西本地雨量站（CMA 区域站网）或雷达定量估测降水（QPE）的融合校正步骤；
2. 在第八节验收指标中增加"降雨输入场偏差评估"子项，而不仅仅检验水动力模型本身的质量守恒与 CSI。

## 四、建议补充的工程规范性事项

1. **初始条件/热启动策略缺失**：`initial_water.tif` 如何生成（冷启动 vs 暴雨前若干天低流量预热 Spin-up）未说明，建议明确采用"暴雨前 24~72h 预热运行 + 以预热终态作为正式计算初始场"的标准做法。
2. **线程配置**：8C/16T 机器上 Numba `prange` 并行建议显式设置 `NUMBA_NUM_THREADS=8`（绑定物理核），避免超线程争用缓存带宽反而拖慢计算密集型数值核心，当前文档未提及线程绑定策略。
3. **下载脚本健壮性**：当前 `download_worldcover_for_region`、`fetch_era5_hourly_point` 均无重试、超时退避与断点续传逻辑，长耗时离线批量下载场景下建议加入 `tenacity` 重试装饰器。
4. **可复现性**：建议即使无 GPU 也构建纯 CPU Docker 镜像（固化 Numba/LISFLOOD-FP 编译环境、依赖版本），避免"本地环境可跑、迁移到生产服务器编译失败"的常见坑。
5. **变电站安全判据闭环**：作为南网应急技术中心项目，久隆阶段应明确给出与变电站实际运行安全挂钩的量化判据（如"围墙顶高程-模拟最大水深 ≥ 0.3m 安全超高"），而不仅是通用的淹没范围 CSI 指标，建议在 8.1 表格"验收关键指标"列为久隆单独增加该项。
6. **时间计划颗粒度不足**：第八节三阶段表只有相对顺序，没有绝对起止日期、人力资源分配与里程碑评审节点，建议补充甘特图或周级排期表，便于工程督办。
